# 像素规格 · 冻结版 v1.0

> 状态：**已冻结**。任何资产不满足本文即为不合格，R14 直接拒。
> 冻结日 2026-11-22 · 依据 DEC-20261122-art-budget（「首周冻结像素规格」）

---

## 1. 原生分辨率

| 项 | 值 | 理由 |
|---|---|---|
| 原生渲染分辨率 | **384 × 216** | ×5 = 1920×1080，整数倍到 1080p |
| 允许的显示缩放 | **1× / 2× / 3× / 4× / 5×**（整数最近邻） | 非整数倍 = 像素大小不均 = 伪像素 |
| 缩放方式 | Nearest-neighbor，**永不** Bilinear / Lanczos | 抗锯齿边缘会杀掉像素感 |
| 视口不铺满时 | 加黑边（letterbox），不拉抻 | 拉抻会破坏 16px 网格 |

> 允许 16:9 之外的资产尺寸吗：**允许**。锚点、立绘、UI 面板都可以是任意尺寸，
> 只要宽高都是 16 的整数倍。

---

## 2. 网格与 tile

- tile 尺寸 **16 × 16**，所有 tile / sheet 的坐标必须落在 16 的整数倍边界。
- 角色帧同栅格：一帧 = 16 的整数倍（默认 16×24 / 32×32）。
- **碰撞与视觉共用同一网格**：TileSet 的 physics layer 多边形顶点也走 16 网格，不许出现 7px 台阶。
- 行走轴（AD）与纵深轴（W/S）在网格上必须正交；纵深节点切换时相机 x 不变（§6b 的「不产生平面坐标漂移」）。

## 3. 调色板（这条是 v1.0 最重要的修订）

`art/palettes/master.gpl` = **32 色**，**按角色分配，不按面积分配**。

### 为什么不是 16 色

第一版按面积抽取 16 色，得到的是 **15 个蓝 + 1 个灰**——暖光全丢了。
而全案唯一的光源语言是「手电一圈暖黄 + 枪口闪光」。16 色按面积分配，必然把它挤掉。

**结论：调色板按角色给配额，色彩总数放宽到 32，单帧仍限 16。**

### 五个家族与配额

| 家族 | 色数 | 角色 |
|---|---|---|
| 冷色阶 c00–c07 | 8 | 世界本身。Day 0→30 只允许整族下移，**不许新增色** |
| 冷光 c08–c10 | 3 | 应急灯、雾、蒸汽。唯一允许"发光"的冷色 |
| 冷光源 c11–c12 | 2 | 出口指示、频段灯（色相偏青，与冷白区分） |
| **暖光 c13–c15** | **3** | **Day 3 之后全案唯一暖色。手电与枪口闪光专用** |
| 土 / 锈 / 血 c16–c20 | 5 | 腐烂 overlay、涂鸦、旧路障、地面拖痕 |
| 中性 / UI c21–c22 | 2 | 归属标记、日记、字 |
| 布 / 皮 c23–c25 | 3 | 校服、书包、消防服、军装 |
| 皮肤 c26–c27 | 2 | 活人与丧尸共用，只靠明度与眼部黑点区分 |
| 死亡 c28–c29 | 2 | 只给丧尸化派生体与尸体 |
| 极值 c30–c31 | 2 | c30 只给枪口闪光中心 1–2 像素；c31 只给贴图内描边 |

### 每类资产的颜色上限

| 类别 | 上限 | 说明 |
|---|---|---|
| tile | **≤ 16** | 实际做法 ≤4 色/tile，留余量给边界过渡 |
| 角色帧 | **≤ 16** | 含皮肤 3 档 + 布 2 档 + 描边 1 档 |
| 武器层 | **≤ 16** | 与角色帧分开计 |
| 背景 / 视差 | **≤ 32** | 允许用满整张板 |
| 风格锚点 | **≤ 32** | 参考图，非游戏内资产 |

## 4. 光

1. **光只来自上方**（横版、室内、无侧顶光）。tile 顶边用 c06_top，底边用 c02_dark。
2. **冷光源只用 c11 / c12 两档**；不许自己调一个「更好看的青」。
3. **暖光只用 c13 / c14 / c15 三档**。Day 0–2 期间允许出现在四处：手电、枪口闪光、
   归属标记、以及"还在响"的指示点。**Day 3 断电当夜之后，暖色只允许出现在两处：手电、枪口闪光。**
4. **发光不做渐变**：亮部到暗部最多两级，中间不插过渡色。
5. 照明是**信息**不是装饰：黑暗拿走的不是亮度，是「那边有什么」。

### 归属标记（已冻结，见 DEC-20261122-marker）

v0.5 的「暖橙 3×5 极淡常驻」与「枪口闪光是 Day 3 之后唯一暖色光源」互相矛盾。
渲染对照后定为 **限时方案 D**：

| 世界日 | 颜色档 | 说明 |
|---|---|---|
| Day 0 | `c14_warm` + 1px `c15_warm_high` | 最亮，用于教学 |
| Day 1 | `c14_warm` | |
| Day 2 | `c13_warm_dim` | 开始像余烬 |
| Day 3（断电当夜） | `c02_dark` | 只剩一个几乎看不见的印子 |
| Day 4 起 | 不绘制 | 再也不会出现 |

三条实现约束：
- **标记顶部不许有亮点像素**——那会把整块读成"一盏小灯"。
- 不做透明度过渡（调色板无 alpha），只做色档退级。
- 形状固定 3×5，位置固定在脚底正中；不允许换成图标、箭头、名字牌。

> 为什么不是妥协：褪掉的那一刻正是世界断电的那一刻。
> **游戏先告诉你「哪个是你」，然后在世界变黑的同时把这个答案收回去。**

## 5. 描边与形状

- 物体**不描纯黑边**；暗部一律用 c02_dark，最深处才用 c31_dead_black。
- 每个 tile 最多 4 色（含底色），超过就要问「这块有必要这么花吗」。
- **不做抖动（dithering）**。抖动会在缩小时变成噪点，且和「平面、干净」的横版构图冲突。
- 可辨识性判据（沿用《逃脱者2》的造型语言）：**关掉 UI、1× 大小下，3 秒内能认出这是什么**。认不出就重画，不是加细节。

## 6. 禁止清单

| × | 说明 |
|---|---|
| 非整数倍缩放 | 包括 1.5×、2.25× |
| 抗锯齿 / 半透明边缘 | 半透边缘在放大后变成脏边 |
| 渐变（>2 档过渡） | 见 §4.4 |
| 抖动 | 见 §5 |
| 调色板外的颜色 | 门禁拒收 |
| 逐帧生成的挥砍动作 | 帧间漂移，改用参数化特效（§6d） |
| 让模型重画熟人丧尸化变体 | 必丢配件位，R25 会拒 |

## 7. AI 参考图 → 真像素：四步管线

模型给的不是资产，是**参考**。转换是确定性的：

```
① 裁切      crop to 目标比例（如 8:5）
② 降采样    BOX（面积平均）÷ N，N = 源图块大小（本例 8）
③ 去噪      MedianFilter(3) —— 这一步决定"像不像手画的"
④ 量化      逐像素吸附到 master.gpl 最近色（不抖动）
```

工具：`tools/pixelpipe.py convert`

```powershell
$PY = "...\dependencies\python\python.exe"
& $PY tools/pixelpipe.py convert <源.png> `
    --palette art/palettes/master.gpl `
    --out art/refs/style_anchors/SA-01_xxx.png `
    --ratio 8:5 --scale 8 --denoise 3
```

**实测**：1024×1024 / 18027 色的模型出图 → 128×80 / 20 色，通过门禁。
跳过 ③ 会得到椒盐噪点（第一版实测过）；跳过 ②④ 会得到「平滑图穿像素服装」。

## 8. 门禁（五条断言，拒收即停）

`tools/pixelpipe.py gate`

| 断言 | 判据 |
|---|---|
| R14a 像素落逻辑格 | 要么是精确整数倍放大，要么原生色数 ≤ 上限。两者都不是 = 伪像素 |
| R14b 仅整数最近邻 | 缩放倍数为整数（非整数倍无法通过判定） |
| R14c 色集在调色板内 | 每个像素颜色必须在 master.gpl 里 |
| R14d 16px 整数边界 | 宽、高都是 16 的整数倍 |
| R14e 单帧 ≤ 上限 | tile / 角色 16；背景 32 |

**对照实测**：模型原始出图 `school_corridor_d3.png` → **FAIL**（18027 色，R14a/c/e 三项违规）。
这就是「真像素 vs 伪像素」的分界线：不是看起来像，是能不能自动证明。

## 9. 风格统一靠什么保证

不是靠「同一个提示词」，而是三件事一起：

1. **唯一取色源**：所有资产只从 master.gpl 取色，且取色时按**角色名**取（`c04_floor`），不按亮度猜。
2. **构造而非生成**：tile 由 `pixelpipe tiles` 从角色名直接画出，**天然合格**，不需要事后修。
3. **门禁拒收**：不合格的进不了 `approved/`，R21 还要人眼签核 + provenance。

第四件事是流程：`generated_candidates/ → approved/` 单向流动，AI 产出默认 draft。
