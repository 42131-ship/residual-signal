## 1. 什么算「开始了」

1. **卡效果字段里出现了其他卡的 `card_id` 引用**——直接耦合，一张卡的逻辑开始依赖另一张的存在或状态
2. **`leftover` 或效果中引入了全局标志位**（如 `global_state.lab_opened`）——跨卡共享状态，改一处影响全局
3. **`trigger_condition` 中出现对玩家历史行为的复合判断**（如"完成过卡 A 且未触发卡 B"）——条件链变长，组合爆炸萌芽
4. **某张卡的 `returns_after_days` 依赖其他卡的触发结果**——时间线开始交织，回归逻辑不再独立
5. **同一插槽被 3 张以上卡竞争**——资源冲突，排序或优先级规则开始膨胀
6. **效果执行需要回溯玩家过去 N 小时的行为日志**——对历史依赖加深,时间窗口查询成本上升

## 2. 三条硬约束

**R30：禁止卡间直接引用** → 卡效果或 `leftover` 中出现其他卡 `card_id` 字符串，校验失败  
**R31：单卡触发条件复杂度上限** → `trigger_condition` 的逻辑节点数（AND/OR/NOT 嵌套层数）≤3 层，超过则失败  
**R32：禁止全局状态副作用** → 卡效果只能修改 `player.inventory` / `player.location` / `player.current_card_state`，写入其他命名空间（如 `world.*` / `global.*`）则失败

## 3. 什么时候该停下来重构

**阈值：任一卡被 ≥2 张其他卡的触发条件引用，或单日内可能同时活跃的卡数 >4**  
到达后第一件事：**画出当前 8 张卡的依赖有向图，标出所有"触发条件→效果→leftover"路径，找出环或扇出度 >1 的节点，拆成事件总线架构（卡只发事件、不直接引用）**
