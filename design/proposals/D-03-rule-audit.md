## 4. 一条你认为应该删掉的规则

需要看具体规则文本，但根据典型模式，最可疑的是**「元数据完整性规则」**——比如「每个资产必须有 `created_date` 和 `last_modified`」。

理由：这类规则在自我安慰「我们很规范」，但实际上 (1) 日期错了不影响游戏运行 (2) 如果真要审计，应该靠 Git 历史而非手写元数据 (3) 维护成本高（每次改文件要记得更新日期），收益为零。

**删除建议**：如果有类似规则，换成 Git pre-commit hook 自动打时间戳，或者干脆承认「我们不需要这个」。43 条规则应该全是「违反了会出 bug」的硬约束，不是流程作秀。
