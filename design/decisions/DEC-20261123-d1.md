# DEC-20261123-D1 · 地图工具链：两个编辑器都不上

> 决策人：主策（本次由执行侧代决，责任在此）
> 依据：`design/D1_COMPARISON.md`（证据表）+ `design/proposals/E-03-d1-review.md`（复核）

---

## 结论

**固定使用 C：不引入 LDtk，也不引入 Tiled。地图由 `data/nodes.json` 驱动，tile 由代码确定性构造。**

这不是"跳过 D1"，是**用 C 让 D1 的前提消失**：D1 门禁的存在意义是在 A / B 之间选一个，
而 A 与 B 要解决的问题（把手工摆的 tile 转成引擎数据）在本项目里**已经由另一条路解决了**。

---

## 为什么 C 是对的（三条，按重要性）

### 1. 拓扑已经是唯一事实源，编辑器只会变成第二个权威

`data/nodes.json` 里已经写着：16 个节点、`axis_x` 0–4、`depth_layer` −1/0/+1、`linked_nodes[]`、`lockable`。
这些被 R01–R09、R30、R41 机械校验，被 `headless_30d.py` 跑过 30 天。

引入编辑器就多一份"地图文件"，它和 nodes.json 冲突时**没有机器能判定谁对**。
而项目最硬的一条规矩是「事实只由状态机产生」——两个权威直接违背它。

### 2. 运行时的碰撞与相机不从编辑器来

`smoke.gd` 在 Godot 4.7 里实跑通过：

```
SMOKE_OK nodes=16 axis=5 rooms=11 day=30 fired=66 sediment_max=14 roundtrip=ok
```

节点是按 `position = Vector2(axis_x * 384, depth_layer * 216)` 从数据建出来的。
**没有任何一步需要编辑器的坐标。** 这也意味着 A/B 的核心卖点（产出 TileMapLayer、带 physics layer 碰撞）
在本项目里是"用不上的能力"。

### 3. 代价确定性

- **A/B 的共同成本**：一个导入器依赖 + 许可证逐条核（Tiled 是 GPLv2）+ PoC 双轨。v0.5 §9 已把「D1 未拍板前的字段冻结」列为短期成本。
- **C 的成本**：要自己写 tile 摆放与画皮的代码。这笔已经在付了——`pixelpipe.py` 从 32 角色板确定性构造 tile，20 格表已过门禁。

## 落败方与理由

| | 落败理由 |
|---|---|
| **A · LDtk + godot-ldtk-importer** | 产出 `TileMapLayer`、physics layer 碰撞、`--headless` 可复现这三项都是它的强项，但**本项目不需要**：拓扑在 JSON 里，碰撞由数据生成，不靠编辑器导出。引入它只为「画 tile 更顺手」，代价是多一个事实源。 |
| **B · Tiled + YATI** | 同上；**另外多一条**：Tiled 本体 GPLv2，虽然「用编辑器产数据」不等于「链接 GPL 代码」，但买断发行前要逐条写清依据——为一个用不上的能力背许可证审查，不划算。 |

## 附加条件（来自 aux 复核，已接受）

`design/proposals/E-03-d1-review.md` 的判决是「C 成立但需附加条件 X」：

> 必须在三周内实现一个极简的 nodes.json 可视化工具（只读预览 + 坐标网格叠加层），
> 否则视觉迭代税会在一个月内迫使团队回退到编辑器。

**接受。** 它点出的三笔成本我认：

1. **视觉调优反馈周期从秒级退化到分钟级**（改 JSON → 重跑 → 起游戏）
2. **人肉编辑器税**：节点从 16 涨到 60 × 8 字段时，手写 JSON 的错误率线性膨胀
3. **onboarding 成本**：编辑器 10 分钟上手 vs 读 schema 2 小时

所以 C 的成立**不是无条件的**。落地顺序：

- **现在**：`tools/nodes_map.py` —— ASCII 拓扑图，让坐标关系一眼可见（已交付）
- **下一项**：`game/tools/node_view.tscn` —— Godot 里只读预览 16 个节点的网格叠加层，能拖相机看，不能改数据
- **红线**：这个可视化工具**只读**。一旦它能写 nodes.json，它就变成了第二个权威，C 的前提当场消失

回退条件里再加一条：

4. 可视化工具上线后，**改一个节点坐标仍然需要超过 3 步操作**（改 JSON → 跑脚本 → 重启），且这种情况每周发生 3 次以上

---

## 回退条件（写死，避免以后吵）

出现以下任一情况，**重开 D1 并补三行实测**：

1. 需要在编辑器里**手摆叙事物件**（不是 tile）：比如某个房间必须在特定位置放一张特定的桌子，而代码摆放成本高于手工
2. 节点的视觉布局与 `nodes.json` 的抽象坐标开始需要**独立维护**（即出现"按数据生成的关卡不好看"这类需求）
3. 关卡数量超过 30 个节点 / 8 个模板，代码摆放的可维护性崩溃
