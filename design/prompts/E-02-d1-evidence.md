## 背景

候选：
- **A**：LDtk（MIT）+ `godot-ldtk-importer`（MIT）
- **B**：Tiled（GPLv2）+ YATI（MIT，Godot 4.3+）

项目形态（关键）：地图**不是**手画的 tile 网格。拓扑已经以 `data/nodes.json` 为唯一事实源：
```
16 个节点 = 5 段主轴（axis_x 0..4，depth_layer 0）+ 11 间纵深房（depth -1/0/+1）
每个房间只挂一段主轴（R30），链接对称（R04），安全屋必须存在（R05）
```
tile 只是这些叙事节点上面的**皮**。运行时读 nodes.json 建碰撞与相机，不需要任何编辑器的坐标。

## 你要产出的表

六行，每行给 A / B / 「不引入编辑器（C）」三列，每列只写两样东西：
1. **结论**（能 / 不能 / 不确定）
2. **依据类型**：`实测` / `文档` / `推断` —— 不许把推断写成实测

维度：
1. 产出 Godot 4.3+ `TileMapLayer`（不是已弃用的 `TileMap`）
2. TileSet physics layer 碰撞能否带过来
3. 许可证与买断发行兼容性（Tiled 是 GPLv2 —— 说清「编辑器程序的 GPL」与「产出数据的授权」是两件事）
4. JSON 可 diff / 可版本化
5. `--headless --import` 在 CI 里可复现（干净 runner 一键重建）
6. 横版纵深适配：`depth_layer` / `linked_nodes[]` / 切镜头换背景的挂接成本

## 最后加一节：新增的第二事实源风险

如果引入编辑器，项目会同时有「nodes.json」和「编辑器地图文件」两个权威。
逐条说明：谁改谁、冲突时以谁为准、CI 怎么拦。**这一节是本次对比的重点。**

## 纪律

- 不要推荐，只给证据表。拍板由主策做。
- 不确定就写「不确定」，并在末尾列出「要确定它需要做什么」。

不超过 900 字。
